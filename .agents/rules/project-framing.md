# Project Framing and Commercial Intent Guidelines

## Scope
Applies to all projects in the portfolio (Revealr, MetroMind, OSA, SortMail, PipelineForge, DevContext/Klarity, AXIOM OS, Dizzy) across all subdomains and main portfolio showcases.

## Core Rules

### 1. Project Nature & Origin
- All projects were created by Rounak Neema either for personal exploration/experimentation or for clients/others as technical engineering solutions.
- Frame each project strictly as an engineering project and showcase of technical capabilities (e.g. "this system has this architecture, solves this engineering problem, and demonstrates these capabilities").
- Clearly indicate what the project does, the technical stack, and the concrete problem it solved.

### 2. Not Turnkey Products for Sale
- None of these projects are commercial SaaS products intended for direct sale, turnkey subscriptions, or self-serve software checkout.
- Never display SaaS pricing tiers, consumer subscription cards ($/month), commercial buy-now buttons, or checkout flows.
- Do not frame these projects as finished consumer apps looking for paying retail users.

### 3. Contact & Interest Intake ("Type Mail Only")
- For anyone interested in a project (e.g. commissioning similar software, technical consulting, private deployment, or codebase access), provide a simple email intake option: "Interested in this? Enter your email" or a direct link to the contact/inquiry page.
- Keep the call to action minimal and direct: type your email or submit a project inquiry.
- Submissions route directly via the automated intake API or contact page (`https://rounakneema.in/contact`).

### 4. Persistence
- Maintain this rule across all current and future updates to project sites, documentation, landing pages, and portfolio descriptions unless explicitly instructed otherwise by the user.
